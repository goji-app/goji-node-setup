API Reference

Send transactional email, manage templates and receive delivery events.

Introduction

The Postline API lets you send transactional email, manage templates and receive delivery events. It is a REST API that accepts and returns JSON, and uses standard HTTP verbs and status codes.

Base URL: https://api.postline.example/v2

Authentication

Authenticate every request with a secret key in the Authorization header. Keys are created in the dashboard and can be restricted to specific domains.

curl https://api.postline.example/v2/messages \
  -H "Authorization: Bearer pl_live_xxxxxxxxxxxx"

Never expose secret keys in client-side code. Use a server or a serverless function to call the API.

Send a message

POST /messages queues a message for delivery and returns immediately.

curl -X POST https://api.postline.example/v2/messages \
  -H "Authorization: Bearer $POSTLINE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "from": "Acme <hello@acme.example>",
    "to": ["jane@example.org"],
    "subject": "Your receipt",
    "html": "<p>Thanks for your order.</p>"
  }'
FieldTypeDescription
fromstringVerified sender address.
toarrayUp to 50 recipients.
subjectstringMessage subject.
html / textstringMessage body. At least one is required.
template_idstringOptional. Use a saved template instead of a body.

A successful response returns 202 Accepted with the message id.

{ "id": "msg_01hq7b2x9k", "status": "queued" }

Templates

Templates use Handlebars-style variables. Create them in the dashboard or with POST /templates, then reference them with template_id and a variables object.

{
  "template_id": "tpl_welcome",
  "to": ["jane@example.org"],
  "variables": { "first_name": "Jane" }
}

Webhooks and events

Postline calls your endpoint when a message is delivered, bounced, opened or marked as spam. Each request is signed with an X-Postline-Signature header; verify it with your webhook secret before trusting the payload.

{
  "type": "message.delivered",
  "data": { "id": "msg_01hq7b2x9k", "to": "jane@example.org" },
  "created_at": "2025-03-04T09:21:07Z"
}

Errors

Errors return a JSON body with a machine-readable code and a human-readable message.

StatusCodeMeaning
400invalid_requestA required field is missing or malformed.
401unauthorizedMissing or invalid API key.
403domain_not_verifiedThe sender domain has not been verified.
429rate_limitedToo many requests. See Retry-After.

Rate limits

Each key may send 10 requests per second and 100 000 messages per day by default. Contact support to raise these limits. Responses include X-RateLimit-Remaining and Retry-After headers.
